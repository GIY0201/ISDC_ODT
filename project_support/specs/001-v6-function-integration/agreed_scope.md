# 단계별 개발 합의

2026-10-01 사용자와 논의한 결정. 초기 spec/plan의 전체 기능 이식 초안보다 이 문서의 합의 범위가 우선한다. 다음 단계는 사용자와 상의하여 진행한다.

## 개발 기준
- 독립 ISDC ODT 프로그램으로 개발하며 AeroDT 계층/파일 규칙을 따른다.
- JavaScript 모듈 + HTML/CSS, CesiumJS, Python/FastAPI를 기준으로 한다. TypeScript/React 도입 초안은 보류한다.
- 핵심 기능부터 구현하고 단계별 검증 결과를 확인한 후 확장한다.
- 첫 기능은 저장된 실제 위성 TLE/OMM 입력에 대한 위성 1개와 지상국 1개의 궤도/가시성 확인이다.
- ISS와 제주 가상 지점, 최소 고도각 10도를 첫 시험안으로 수용했다. 10도는 시험용 설정이며 실제 지상국 장비 기준으로 확정하지 않는다.

## 실제 통신 조건 확인 및 적용: 후속 필수 요구
2026-10-01 사용자 지시: 가시성 방식으로 시작하되 실제 통신 조건을 반드시 확인하고 적용한다. 단순 권장 또는 선택 기능으로 취급하지 않는다.

통신 단계 진입 전에 대상 위성의 통신 서비스와 지상국 장비를 특정하고 공식 자료/장비 사양/운용 조건을 확인한다. ISS 궤도 시험은 ISS 통신 서비스 이용 가능성을 뜻하지 않는다. 임의의 송수신기 기본값을 실제 장비 사양으로 사용하지 않는다.

확인/적용 항목:
- 지상국 실제 위치와 높이, 방위각별 지형/장애물 고도각 제한, 안테나 지향 및 추적 범위.
- 송수신 주파수와 대역폭, 변조/부호화, 데이터율, 송신 출력, 안테나 이득/편파 및 지향 손실, 수신 성능.
- 위성 거리와 도플러 변화, 전파 경로 및 대기/강우 손실 등 해당 주파수에 필요한 링크 계산과 여유 기준.
- 대상 서비스의 운용 모드, 사용 권한과 예약/가용성, 실제 연결 장비 및 송수신 기록의 유무.

각 입력은 값/단위/출처/자료 버전 또는 확인일/적용 범위/실측 또는 가정 여부를 기록한다. 확인되지 않은 필수 입력은 미확인으로 남기고 통신 가능 판정을 보류한다.

결과와 완료 기준:
1. 기하학적 가시 구간: 궤도와 고도각 조건을 만족한다.
2. 모델상 통신 조건 충족 구간: 확인된 서비스/장비 입력과 링크 조건을 만족한다. 실제 성공을 뜻하지 않는다.
3. 실제 통신 확인 구간: 해당 시각의 수신/복호/장비 기록 등 증거가 있다.

세 결과는 UI와 산출물에서 구분한다. 실제 통신 입력의 출처 확인, 계산 적용과 정상/실패/미확인 조건 시험이 끝나기 전에는 통신 기능 완료로 기록하지 않는다. 실장비 증거가 없으면 모델 검증으로만 보고한다.

현재 단계: 요구사항 합의 기록. 통신 사양 조사/적용 및 기능 구현은 아직 실행하지 않았다.
