# 선배 기능 전체 이식 실행 계획 · 2026-10-07

사용자 목표: 기존 선배 구현의 모든 기능을 승인된 V6 UI로 이식한다. 독립 제품과 AerODT 계층·파일 규칙, JavaScript/FastAPI/Rust, 고정 8891, 같은 작업 브랜치, 원본 기능과 사용자 데이터를 보존한다. 01:00은 완료 시한이었다. 중단 시각으로 해석한 것은 오류다. 이어 01:45를 목표로 계획했고, 약01:30에 사용자가 07:00 완료 가능 여부를 물었다. 에이전트는 07:00을 더 현실적인 전체 이식·검증 목표로 답했고 완료 보장은 하지 않았다. 시각 도달 자체가 중단 지시는 아니다.

## 실행 순서와 담당

이전 사용자 병렬 작업 동의를 적용해 독립 파일에 한해 분담한다. 데이터와 공용 application/UI 조립은 주 에이전트가 담당한다. 보안, 설정, 시나리오 구성요소는 각각 분리한 에이전트가 담당하고 공용 조립 파일·서버·Git은 수정하지 않는다. 시나리오가 필요한 모듈은 조립 후에만 활성화하며 누락 dependency는 미연결로 표시한다.

- 01:08–01:30 목표: 정상 임무 route 보완; 데이터·보안·설정·시나리오 원본 이식과 focused regression; 공용 factory/V6 조립.
- 01:30–01:40 목표: 전체 Python/Node 회귀와 실제 8891 Chrome에서 조회·명령·오류·두 해상도 검증. backend 전환 전 현재 SIM/GP/배치/모듈 상태 캡처. 복원할 수 없는 수락 작업이 있으면 먼저 보존 방안을 처리한다.
- 01:40–01:45 목표: 발견된 연결 결함 수정, 선배 기능 목록 재대조, 실제 다운로드 파일 대조, 같은 브랜치의 로컬 변경 기록.

이 시간표는 실행 목표이며 완벽한 전체 완료 보장이 아니다. 시간 부족을 이유로 원본 기능·수용 기준을 삭제하거나 시험을 건너뛰어 완료로 표시하지 않는다. 01:45 상태는 완료/부분 연결/실패/미검증을 구분해 보고하고 남은 작업을 계속한다. 실제 RF·HIL·장비 인증은 선배 모의 기능 이식과 구분한다.

## 07:00 목표의 후속 배분

- 01:30–02:00 목표: 데이터·보안·설정 실제 화면과 전체 회귀 결함 마무리. 시나리오 정의와 현재 막힌 SIM UTC prerequisite를 구분해 표시.
- 02:00–04:00 목표: 기존 공용 표시/노드/native query owner를 통해 원본 PoC의 실제 SIM UTC 계산 입력, 군집 배치·다섯 임무·통신망·장애·복구 단계 실행을 조립·검증. 원본 수락 증거와 source 역할을 유지.
- 04:00–05:30 목표: T075–T084 원본 기능 재대조, 데이터 서비스·복구/DTN·네 서비스 임무 lifecycle/화면 간 인계/다운로드 파일 bytes 검증.
- 05:30–07:00 목표: 전체 회귀, 실제 두 해상도·다중 창·실패/복원 검증, 발견 결함 수정, 미완료 목록과 로컬 버전 관리 기록 정리.

의존성 발견 시 순서를 조정하며 의미 있는 위험은 즉시 알린다. 미확인 기능을 시간표만으로 완료 판정하지 않는다. 기존 보류·미선정 실제 장비 조건과 선배 원본의 SIM/stand-in 범위를 보존한다.

## 완료 판정

각 기능은 원본 source 근거→계층에 맞춘 실제 재사용→API/owner/UI 연결→회귀→실화면 증거까지 연결한다. 검증용 실행은 별도 이름과 범위를 사용한다. 다섯 폼을 표시하는 것은 다섯 lifecycle 완료가 아니다. 전체 시험 통과는 모든 화면/모델/다운로드 성공을 대신하지 않는다. T075–T084는 전체 기준을 만족하기 전까지 미완료로 유지한다.
