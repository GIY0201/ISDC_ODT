## Clarifications

### Session 2026-10-03
- Q: 다음 첫 기능은 선배 프로그램의 RF 계산기를 새 UI에 연결하는 것부터 시작할까요? → A: A. 사용자가 모든 입력값을 직접 설정하는 RF 계산기부터 연결한다. 실제 서비스·장비 조건 조사와 적용(F001)은 계속 필수 후속으로 유지한다. 프레임 성능 확인(T032)은 나중에 재개한다.

### Session 2026-10-01
- Q: 첫 단계는 계산 구현의 정확성을 검증하고 실제 ISS 위치 오차 평가는 후속으로 분리할까요? → A: 사용자 동의. 첫 단계는 동일 입력/조건의 기준 계산과 일치 검증으로 평가하고, 실제 ISS 위치 오차는 별도 관측 자료 기반 후속 평가로 분리한다. 수치 허용 오차는 후속 Q3 동의로 확정했다.

- Q: 첫 단계 사용성 목표는 어떤 수준으로 설정할까요? → A: 사용자 지시로 게임 기준의 부드러움과 즉각 반응을 목표로 한다. 30fps 제안은 대체한다. 2026-10-01 후속 사용자 동의로 구체 목표는 60fps, 입력 피드백 50ms, 시간 변경 결과 100ms, 하루 가시 구간 계산 1초로 확정했다. 고주사율 120/144fps는 현재 요구가 아니다.

- Q: 기준 계산 대비 위치 10m, 고도각 0.01도, 가시 구간 경계 1초를 허용 오차로 삼을까요? → A: 사용자 동의. 동일 궤도 자료/시각/좌표계/계산 조건의 기준 결과와 비교한다. 실제 ISS 위치 오차 보장은 아니며 라이브러리 공식 검증의 더 엄격한 기준은 별도로 유지한다.

## User Scenarios & Testing

### User Story 1 - 위성 위치와 시간을 확인 (Priority: P1)
사용자는 V6 공용 지구와 위성 작업 창에서 위성 하나의 위치를 특정 UTC 시각에 확인한다.
**Why this priority**: 후속 가시성 및 통신 계산의 입력과 시간 기준을 먼저 검증한다.
**Independent Test**: 저장된 ISS 궤도 자료를 열고 시각을 이동한 뒤 같은 시각으로 돌아와 위치와 자료 출처를 비교한다.
**Acceptance Scenarios**:
1. **Given** 출처와 기준시각이 기록된 저장 자료, **When** 위성을 열면, **Then** 식별자, 자료 기준시각, 현재 UTC와 계산 위치가 표시된다.
2. **Given** 정지한 화면, **When** 시각을 앞뒤로 이동하면, **Then** 위치와 수치가 같은 시각을 나타내며 같은 입력으로 돌아왔을 때 같은 결과가 재현된다.
3. **Given** 손상되거나 지원하지 않는 자료, **When** 불러오면, **Then** 이유를 표시하고 임의 위치를 실제 계산 결과로 표시하지 않는다.

### User Story 2 - 지상 지점에서 가시성을 확인 (Priority: P1)
사용자는 제주 가상 지점의 좌표와 고도각 조건으로 위성이 보이는 시각 구간을 확인한다.
**Why this priority**: 통신 조건을 추가하기 전에 기하학적 조건을 독립적으로 검증한다.
**Independent Test**: 같은 위성/시각/지점에서 고도각 조건을 변경하고 가시 구간을 비교한다.
**Acceptance Scenarios**:
1. **Given** 공개된 가상 지점 좌표/높이와 10도 조건, **When** 조회하면, **Then** 고도각, 가시 여부 및 지정 시간 범위의 진입/이탈 UTC를 확인할 수 있다.
2. **Given** 계산 고도각이 설정값과 같거나 그 이상, **When** 판정하면, **Then** 기하학적으로 가시라고 표시한다. 미만이면 비가시다.
3. **Given** 유효한 탐색 범위에 가시 구간 없음, **When** 계산하면, **Then** 구간 없음으로 표시한다. 입력/계산 실패와 구분한다.
4. **Given** 통신 장비 및 서비스 자료 미확인, **When** 가시 구간을 확인하면, **Then** 실제 통신 가능/성공으로 표시하지 않는다.

### User Story 3 - 작업 중 입력과 화면 유지 (Priority: P2)
사용자는 지구를 조작하고 작업 창을 이동/최소화/복원하면서 선택 시각과 지점을 유지한다.
**Why this priority**: 확정 UI 안에서 기능이 끊김 없이 사용되는지 확인한다.
**Independent Test**: 작업 창 최소화/복원과 지구 조작 후 선택값 및 표시 시각의 일치를 확인한다.
**Acceptance Scenarios**:
1. **Given** 선택된 위성/시각/지점, **When** 창을 최소화하고 복원하면, **Then** 입력과 결과를 유지한다.
2. **Given** 자료 오류, **When** 다른 시각/지구 조작을 하면, **Then** 조작이 가능하고 오래된 결과에는 이전 계산 시각과 상태를 표시한다.

### Edge Cases
- RF 입력의 빈 값/비유한 수치/허용 범위 위반, HTTP 오류, 요청과 다른 입력의 응답은 정상 모델 결과로 표시하지 않는다. 편집/재계산/취소 후 늦은 응답은 현재 결과를 덮어쓰지 않는다. 모델 결과가 준비된 화면을 다시 열면 입력과 결과 사본을 유지한다.
- 궤도 자료의 오래된 기준시각: 자료 나이를 표시하며 오래됨 정책은 계획에서 근거와 함께 선정한다.
- 시간대 없는 시각, 잘못된 좌표/높이/고도각, 역전된 시간 범위: 입력 오류를 표시한다.
- 탐색 범위 시작/끝에 걸친 가시 구간: 잘린 구간임을 표시한다.
- 계산 중 시각을 다시 변경: 이전 시각 결과가 최신 선택 결과를 덮어쓰지 않는다.
- 지구 표시 자원 실패: 수치/오류를 확인할 수 있고 지구 렌더링 실패를 정상으로 숨기지 않는다.
- 작은 화면: 1280x720과 1920x1080에서 주요 입력과 창 복원 조작에 접근할 수 있다.

3. **Given** 채택V6의별도창버튼, **When** 현재작업을같은origin의별도창에열고입력을변경하면, **Then** 작업/입력사본과runtime revision을유지하고동시편집충돌과팝업차단을표시한다. 문서당Viewer는하나이며원문서지구는유지한다.

## Requirements

### Functional Requirements
- **FR-001 (R002,R005)**: 첫 단계는 저장된 실제 위성 하나와 지상 지점 하나를 V6 공용 지구/작업 창에서 다룬다.
- **FR-002 (R005,R007)**: 궤도 자료의 식별자, 출처, 기준시각과 선택 UTC를 결과에 연결하고, 실제 관측 위치와 예측 위치를 혼동하지 않는다.
- **FR-003 (R005)**: 시간 이동, 정지, 재생 및 같은 시각으로 복귀를 제공하고 표시 시각을 위치/수치와 일치시킨다.
- **FR-004 (R005)**: 지점 좌표/높이와 조절 가능한 최소 고도각을 명시하고 고도각과 지정 범위 내 가시 구간을 계산한다.
- **FR-005 (R006,R007)**: 가시성 결과는 기하학적 판정으로 표시한다. 실제 통신 입력이 없으면 통신 조건은 미확인이다.
- **FR-006 (R002,R009)**: 창 이동/최소화/복원과 지구 조작에서 입력을 유지하며 처리 중/실패/이전 결과를 구분한다.
- **FR-007 (R001)**: AeroDT를 설치하지 않아도 독립 실행한다. 공유 가능한 구조 제약은 개발 원칙과 계획에서 검증한다.
- **FR-008 (R003,R004,R006,R010)**: 후속 통신/임무/분석/모의 시험/SIM 제어의 범위 및 증거를 계속 추적하고 단계별 검토 후 확장한다.
- **FR-009 (R002,R003,R004,R007)**: V6 지상국 창에서 링크 이름과 RF 수치 10개를 모두 직접 입력하여 선배 계산의 결과를 조회한다. 기본 장비값을 숨겨 자동 적용하지 않는다. 요청 입력과 결과 단위/모델/가정을 함께 표시하고 실제 통신은 미확인으로 유지한다. 거리도 직접 입력하며 현재 궤도·가시 구간의 통신 판정을 바꾸지 않는다. 입력과 결과 사본을 화면 전환/창 복원에서 유지하고 별도 창 전달값은 다시 계산한다.

### Key Entities
- RF 입력/모델 결과: 편집 가능한 링크 식별자, 주파수/거리/출력/송수신 이득/기타 손실/대역폭/데이터율/잡음온도/요구 Eb/N0, 요청 입력 사본, 모델 식별자, 단위가 있는 수치 8개, 기존 모델 분류와 계산 가정. 실제 장비 또는 통신 증거가 아니다.
- 궤도 자료: 위성 식별자, 요소, 출처, 기준시각, 확보 시점.
- 지상 지점: 이름, 위도/경도, 높이와 기준, 가상 여부, 최소 고도각.
- 계산 결과: 입력 자료 식별자, UTC, 위치, 고도각, 유효/실패 상태.
- 가시 구간: 시작/끝 UTC, 적용 고도각, 탐색 범위 경계 여부. 통신 성공 기록이 아니다.

## Success Criteria

### Measurable Outcomes
- **SC-007**: RF 수치 10개와 링크 이름의 편집값이 요청/결과에 모두 일치한다. 기존 API의 수치와 분류를 유지하며 표시용 반올림으로 분류를 다시 계산하지 않는다. 빈 값/범위 위반/HTTP 실패/불일치 응답/역순 응답에서 정상 결과 오표시 0회. 두 해상도에서 계산과 입력 조작 가능, 최소화/복원/화면 재구성 후 입력 유지, 별도 창 편집 반영 후 이전 결과 비표시를 검증한다. RF 계산 전후 궤도 상태/가시 결과의 실제 통신 미확인 의미는 유지한다.
- **SC-001**: 정상 저장 자료 1세트로 위성/지점/UTC/위치/고도각/가시 구간을 한 흐름에서 확인한다.
- **SC-002**: 같은 입력/시각으로 돌아왔을 때 결과가 재현되고, 동일 입력/좌표계/계산 조건의 기준 결과와 합의된 수치 허용 오차 안에서 일치한다. 첫 단계 완료 기준은 계산 구현 검증이다. 실제 ISS 위치 오차는 별도 관측 자료 기반 후속 평가로 분리한다. 기준 결과 대비 위치 벡터 차이 10m 이하, 고도각 절대 차이 0.01도 이하, 가시 구간 시작/종료 시각 차이 각각 1초 이하를 수용 기준으로 삼는다. 같은 입력으로 복귀했을 때의 재현성과 기준 계산 일치 여부는 각각 시험한다. 라이브러리 공식 검증 기준이 더 엄격하면 별도 시험으로 유지한다. 기준 자료/버전, 좌표계, 중력 상수/계산 모드와 시간/높이 변환을 계획에서 고정한다.
- **SC-003**: 잘못된 자료, 잘못된 시각, 가시 구간 없음, 경계에서 잘린 구간의 네 경우를 정상/오류로 구분한다.
- **SC-004**: 창 최소화/복원 후 위성/지점/시각 입력 3개가 모두 유지되고 두 기준 해상도에서 주요 조작에 접근한다.
- **SC-005**: 첫 단계의 모든 결과에 예측/가상/기하 가시성의 해당 의미가 표시되고 실제 통신 성공 표시가 없다.
- **SC-006**: 시간 이동과 창/지구 조작의 응답시간 및 화면 갱신을 측정하여 사용자와 합의한 목표로 검증한다. 사용자 지시에 따라 게임 기준의 부드러움과 즉각 반응을 목표로 한다. 첫 단계 위성 1개/지점 1개, 로컬 실행, 초기 로딩 완료, 60Hz 이상 화면과 전경 탭에서 60fps를 목표로 한다. 창/지구 조작의 프레임 간격 95백분위 16.7ms 이하, 입력 화면 피드백 95백분위 50ms 이하, 시간 변경 결과 표시 95백분위 100ms 이하, 하루 가시 구간 계산 95백분위 1초 이하를 수용 기준으로 삼는다. 계산 중에도 조작 가능하고 이전 결과 덮어쓰기는 0회다. 브라우저/GPU/전원/해상도와 99백분위/최댓값도 기록한다. 측정 절차는 validation_targets_proposal.md를 따른다. 2026-10-03 실제 계측 결과는 validation/t028_performance.md에 기록했으며 현재 SC-006 미달이다. 합의 목표는 유지한다.

## Assumptions
- 승인된 RF 첫 묶음은 기존 범용 계산기 연결이다. 실제 서비스 프로파일, 도플러/장비 추적, 모델 충족 구간과 실제 수신 확인은 F001 후속이다. RF 입력은 모두 사용자 가정이며 실제 ISS 사양을 기본값으로 지정하지 않는다.
- ISS, 제주 가상 지점과 10도는 합의된 초기 시험안이다. 정확한 가상 좌표/높이와 시간 범위는 계획에서 명시하며 실제 시설로 주장하지 않는다.
- 첫 단계는 재현 가능한 저장 궤도 자료를 사용한다. 실시간 카탈로그 갱신과 다수 위성 확장은 이후 범위다.
- 전체 목표에는 선배 기능의 단계별 연결이 남아 있다. 재사용 방식과 다음 연결 순서는 첫 단계 검토 결과를 보고 결정한다.
