## Selected native geometry and primitive lifecycle

The existing catalog timeline is the display UTC owner. Inject `sampleAt(utc)` and `advanceUtc(utc,seconds)` into the renderer; these reuse the current readonly sample buffer/UTC codec. Values carry selected number/GP hash and frameITRF, finite position_m[3], canonical UTC, interpolation/quality metadata. A missing sample is null. No Date-based UTC rounding, JavaScript SGP4, prediction outside the buffer, or new clock. At epoch before a buffer exists, only that exact valid epoch position is available.

Reuse `SatelliteModelLayer` algorithms under visualization with native Cartesian3 position construction instead of original lon/lat propagation callback. Native-buffer position at utc+1s may supply the original forward-difference display direction; if missing use original ENU approximation and disclose it. This is display attitude, not independent velocity/attitude measurement. Renderer receives the UTC codec callback; it imports neither application state nor transport. It keeps one selected model primitive, not another state authority. Same satellite/URL/scale reuses a loaded primitive and updates geometry without reloading. Model selection always checks satellite/GP generation; async load completion updates to the latest injected geometry, never the request-start position. Clear/newselection/disposal invalidate loads and ready/error callbacks, remove only owned primitives/listeners, destroy late returned primitives and cancel pending focus.

Display states distinguish unassigned, loading, ready, error and hidden_no_geometry. Cesium `fromGltfAsync` return alone is not render-ready proof: wait for actual ready/render evidence. Failure/retry keeps valid point representation; explicit retry is allowed and old failures cannot override a newer selection. No model or following on a failed/missing native position. GPU render errors must be reported separately from transport/manifest errors. Existing catalog points/selected point/track/stations remain intact.
