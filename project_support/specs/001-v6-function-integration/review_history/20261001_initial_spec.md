# Feature Specification: 독립 ISDC ODT V6 기능 연결

**Feature Branch**: 없음 (기존 폴더 보존)
**Created**: 2026-10-01
**Status**: Draft — 사용자와 기능 범위/언어/환경 논의 전. 구현 진입 금지.

**합의 업데이트**: [agreed_scope.md](agreed_scope.md)의 단계별 핵심 기능 범위와 언어 기준을 우선한다. 아래 전체 이식 내용은 초기 검토 초안이며 이번 단계의 완료 요구가 아니다. 실제 통신 조건 확인과 적용은 후속 필수 요구다.
**Input**: 확정된 V6 UI에 선배 ISDC-ODT 기능을 연결하고 AeroDT 구조 규칙을 공유하는 독립 프로그램을 개발한다.

## User Scenarios & Testing

### User Story 1 - 공용 공간과 작업 창 (Priority: P1)
사용자는 지구 공간 상황을 유지하면서 역할별 작업을 연다.
**Why this priority**: 채택된 V6의 핵심 탐색 방식이다.
**Independent Test**: 궤도 작업을 열고 이동, 크기 변경, 최소화, 복원, 확장 및 별도 창을 확인한다.
**Acceptance Scenarios**:
1. **Given** 공용 지구 화면, **When** 위성 작업을 선택, **Then** 기존 위성 검색과 궤도 필터를 사용한다.
2. **Given** 열린 작업, **When** 최소화 후 복원, **Then** 입력과 선택이 유지된다.
3. **Given** 작은 화면, **When** 작업 확장, **Then** 스크롤로 모든 조작에 접근한다.

### User Story 2 - 선배 기능 사용 (Priority: P1)
운용자는 통신, 임무, 분석, 시험과 실행 제어를 같은 공간에서 사용한다.
**Why this priority**: 화면 시안을 동작하는 프로그램으로 연결한다.
**Independent Test**: RF 계산, 임무 편집/재계획, 보고서 내려받기, MOCK-HIL 시험 및 SIM 정지/스텝을 실행한다.
**Acceptance Scenarios**:
1. **Given** 역할별 목록, **When** 지상국/임무/비교/EM 작업을 열고 실행, **Then** 선배 프로그램의 동일 계산과 결과가 나타난다.
2. **Given** 미구현 보안/시설/실측 흐름, **When** 해당 작업을 선택, **Then** 미연동 설명이 나타나며 실제 명령을 전송하지 않는다.

### User Story 3 - 독립 실행과 데이터 의미 (Priority: P2)
개발자는 AeroDT 없이 ISDC ODT를 실행하고 기능의 출처와 한계를 확인한다.
**Why this priority**: 독립 프로그램 결정과 향후 이식 요구를 만족한다.
**Independent Test**: 다른 작업 디렉터리에서 실행하고 API 및 출처 표시를 확인한다.
**Acceptance Scenarios**:
1. **Given** 독립 프로그램, **When** 실행, **Then** AeroDT 경로를 참조하지 않는다.
2. **Given** GP/SIM/MOCK-HIL 결과, **When** 화면/산출물을 확인, **Then** 실측이나 실제 HIL로 표시하지 않는다.

### Edge Cases
- 팝업 차단 시 안내하고 현재 작업을 유지한다.
- 브라우저 뒤로/앞으로와 알 수 없는 작업 주소는 안전한 공용 화면으로 돌아간다.
- 외부 카탈로그/지구 라이브러리 실패는 기존 stale/미제공/합성 표시를 유지한다.
- 서버 단절은 기존 스트림 재연결 알림을 유지한다.
- 창 이동/크기 변경은 버튼과 키보드 대안도 제공한다.

## Requirements

### Functional Requirements
- **FR-001**: 공용 지구, 역할별 목록과 V6 작업 창 구조를 제공한다.
- **FR-002**: 창 이동, 크기 조절, 최소화, 복원, 확장, 닫기와 별도 창 열기를 제공한다.
- **FR-003**: 기존 궤도/통신/임무/분석/MOCK-HIL 다섯 기능과 SIM 실행 제어에 접근할 수 있다.
- **FR-004**: 기존 계산, 명령, 내보내기 의미와 결과를 보존한다.
- **FR-005**: UI 선택과 서버 현재 상태를 구분하고 별도 창은 같은 서버에서 상태를 읽는다.
- **FR-006**: GP, SIM, MOCK-HIL, 합성, 미연동을 실측과 구분한다.
- **FR-007**: 독립 실행과 AeroDT 계층/명명 규칙을 유지하고 UI 및 개발 규칙을 문서화한다.
- **FR-008**: 입력 유지, 오류 안내, 키보드 접근과 1280x720 및 1920x1080 화면에서 작업 접근을 검증한다.

### Key Entities
- 작업: 역할, 이름, 연결 기능, 현재 선택, 지원 여부.
- 작업 창: 위치, 크기, 최소화/확장 상태. 물리 상태를 소유하지 않는다.
- 관측 사본: 기존 서버 run ID, 모의 시간, 위성 선택과 데이터 출처.

## Success Criteria

### Measurable Outcomes
- **SC-001**: 다섯 기존 기능 모두 역할별 작업 목록에서 접근 가능하다.
- **SC-002**: 최소화/복원과 기능 전환 후 기존 입력이 유지된다.
- **SC-003**: 두 기준 해상도에서 창 제어와 기능 조작이 가려지지 않는다.
- **SC-004**: 기존 기능 회귀시험의 결과가 유지되고 새 창 동작 및 실제 웹 흐름을 확인한다.
- **SC-005**: 모든 미지원 역할은 미연동으로 표시하며 실제 명령 성공을 주장하지 않는다.

## Assumptions
- 로컬 기존 코드를 보존하고 GitHub 기준 버전과 비교한다.
- 이번 범위는 선배가 이미 구현한 기능의 V6 연결이다. V6의 미구현 실측/보안/시설/EM 실장비는 후속 기능이다.
- 별도 창은 서버 상태를 공유하되 UI 선택은 각 창에서 유지한다. 기존 V6 mock의 전역 입력 복제는 운용 계약으로 채택하지 않는다.
- 실제 운용 인증/권한 체계와 영구 recording/replay 구현은 범위 밖이며 기존 한계를 유지한다.
