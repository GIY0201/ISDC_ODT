# 통합 관제 현황판 구성안

2026-10-07. 현재 구현된 데이터 소유자와 화면을 확인한 제안이다. 이 문서는 새 현황판 구현 완료 보고가 아니다.

## 목적

위성군, 임무, 교신, 데이터 전달의 상태를 한 화면에서 파악하고 확인이 필요한 대상의 담당 화면으로 이동한다. 절차 설명, 설정 편집, 모의실험 실행 버튼은 각 업무 화면에 둔다.

## 화면 배치

상단에는 핵심 숫자 카드 여섯 개를 둔다. 가운데 왼쪽은 지구 지도, 오른쪽은 임무와 시스템 상태 분포를 둔다. 아래에는 지상국 접촉 일정과 데이터 전달 추이를 둔다. 상세 설명과 출처는 항목 제목 오른쪽 i로 연다. 현황판의 업무 요약을 보기 위해 내부 스크롤을 요구하지 않는다.

| 구역 | 기본 표현 | 표시할 정보 | 상세 이동 |
|---|---|---|---|
| 위성군 | 큰 숫자와 지도 | 운용 대상 수, 위치 표시 가능 수, 선택 위성 위치 | 위성 상태 및 궤도 |
| 임무 | 상태별 수치와 가로 누적 막대 | 계획, 수행 중, 완료, 중단 건수 | 임무계획 및 결과 |
| 교신 | 숫자와 지상국별 시간 막대 | 현재 계산된 가시 구간, 다음 접촉까지 남은 시간, 예정 구간 | 지상국 및 통신 |
| 시스템 연결 | 색상별 숫자 카드 또는 가로 막대 | 연결, 단절, 대기, 미확인 개수 | 시스템 연동 설정 |
| 데이터 전달 | 단계별 수치와 추이 | 저장, 전달 대기, 수신 확인 건수와 처리량 | 임무 데이터 관리 |
| 확인 필요 | 숫자와 짧은 목록 | 실제 연동된 경보 또는 별도로 표시된 모의실험 장애 | 운용 판단 및 인계 |

카탈로그 전체 위성 수는 운용 대상 수와 별도로 표시한다. 임무가 없는 경우와 조회되지 않은 경우를 구분한다. 데이터가 없는 항목은 0이나 정상으로 채우지 않고 회색 미확인 상태로 표시한다. 색상에는 짧은 상태명과 숫자를 함께 제공한다.

## 현재 데이터로 가능한 범위

- `workspace_context.js`: 수락된 위성 배치 개수, 모의실험 실행 상태, 선택 임무의 계획 수락 상태, 검증된 통신 조회, 검증된 데이터 객체 개수. 현재 선택 임무 하나만으로 전체 임무 분포를 만들면 안 된다.
- `settings/topology.js`: 현재 운용 모드의 시스템 연결 상태 개수. 내장 연결과 실제 장비 연결은 별도 의미이므로 i에 진단 방식과 확인 시각을 제공한다.
- `tabs/mission_workspace.js`: 서버 임무 목록의 상태와 진행률. 모의실험 자료라는 출처 표시를 유지한다.
- 지상국 화면의 조회 결과: 입력과 분석 시각이 일치하는 결과에 한해 예정 가시 구간을 표시한다. 가시 구간은 실제 교신 성공이 아니다.
- 데이터 조회는 현재 보유 자료만으로 표현한다. 연속 시계열이 없으면 처리량 추이 그래프를 임의로 생성하지 않는다.
- 실제 원격측정과 운영 경보가 아직 연동되지 않았다. 위성 건전성 정상률, 실제 경보 수, 교신 성공률은 아직 표시할 근거가 없다.

## 구현 순서

1. 기존 글 위주의 여섯 요약 카드를 숫자 중심으로 바꾸고 각 항목의 상세 이동을 유지한다.
2. 전체 임무 목록과 연결 진단을 현재 소유자에서 읽어 상태 분포를 추가한다.
3. 조회된 접촉 구간을 지상국별 시간 막대로 표시한다.
4. 검증된 시간별 표본이 확보된 데이터에만 추이 그래프를 추가한다.

현재 시각과 분석 시각은 아래의 공용 시계를 사용한다. 현황판에서 새로운 시계를 만들거나 조회할 때 실행 상태를 변경하지 않는다. GP 궤도 계산, 모의실험, 실제 측정 자료의 구분은 한 줄의 출처 배지와 i로 제공한다.

업무 구분의 참고 자료는 [ESA 운용 담당 업무](https://www.esa.int/Enabling_Support/Operations/Who_does_what_at_ESA_Mission_Control)와 [CCSDS 임무계획 및 일정](https://ccsds.org/Pubs/529x0g1.pdf)이다. 한국어 메뉴는 실제 제품의 목적을 표현하는 번역이며 특정 센터의 공인 UI 표준으로 주장하지 않는다.

## 두 상황판의 관리 대상

사용자가 확정한 구분은 다음과 같다. 통합 관제 상황판은 실제 위성의 운용과 관리를 위한 화면이다. DT 통합 상황판은 가상 시나리오와 DT 모듈의 통합 관리를 위한 화면이다. 관리 대상과 자료 출처를 메뉴, 제목, 수치 집계에서 분리한다.

실제 상황판의 건전성, 실제 교신, 운영 경보와 실제 데이터 수신은 실제 연동 근거가 있어야 표시한다. 아직 실제 연동이 없는 항목에 모의실험 수치를 대신 채우지 않는다. 공개 궤도 자료에 의한 계산 위치는 자료 기반 계산이라는 출처를 유지한다.

## DT 통합 상황판

사용자 요청에 따라 DT 작업공간의 첫 화면으로 추가할 구성안이다. 가상 시나리오, 모듈 간 연결과 데이터 흐름, 실행 상태, 결과를 함께 요약한다. 기존 데이터 소유자를 읽으며 별도 실행 상태를 만들지 않는다.

| 구역 | 표현 | 내용과 상세 이동 |
|---|---|---|
| 시험 요약 | 큰 숫자와 상태 배지 | 선택 시나리오, 준비 여부, 모의실험 실행/정지, 경과 시간, 실행 속도. 시험 시나리오 작성 및 실행 기록으로 이동 |
| 시험 구성 | 숫자 카드와 간단한 구성도 | 위성 수, 지상국 수, 연결 확인/미확인 수. 시험 환경 구성 및 시스템 연동 설정으로 이동 |
| DT 모듈 통합 관리 | 연결 구성도와 상태별 숫자 | 모듈별 준비/실행/중단/연결 끊김/미확인 상태, 데이터 입력과 출력 경로, 최근 응답 시각. 실제 제공되는 상태만 표시하고 연결됨을 실행 중으로 간주하지 않음 |
| 진행 단계 | 단계도와 현재 위치 | 정상, 장애 모사, 우회, 복구. 현재 시나리오에 정의되고 기록된 단계만 표시 |
| 성능 변화 | 시간 그래프와 사건 표시 | 전력, 지연, 손실, 처리량. 동일 실행의 실제 수신 시계열이 있을 때만 표시 |
| 기준 대비 결과 | 나란한 막대 또는 비교 표 | 정상/장애/우회/복구의 단위별 차이. 검증된 단계별 결과를 사용하고 결측은 빈 상태로 유지 |
| 시험 판정 | 통과/미달/미판정 건수 | 결과와 판정 기준, 미달 항목의 짧은 목록. 시험 결과 평가로 이동 |

상단은 활성 시나리오와 모듈 상태 수치, 중앙은 DT 모듈 연결/데이터 흐름 구성도와 시나리오 진행 단계, 하단은 성능 추이와 결과로 배치한다. 단순한 시험 결과 대시보드로 한정하지 않는다. 설정 편집, 장애 주입, 리셋, 배포는 상황판에 중복 배치하지 않는다. 각 항목 클릭 시 해당 기능의 유일한 편집 화면을 연다.

현재 실행 하나의 결과를 전체 시험 통계처럼 표시하지 않는다. 시험 이력이 없으면 누적 통과율 그래프는 제공하지 않는다. 궤도 계산, 모의실험, 장비 연동 시험의 자료 구분을 표시한다. 관제 수치와 모의실험 수치를 같은 분포의 값으로 합산하지 않는다.
