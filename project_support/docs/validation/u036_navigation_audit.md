숨김/잘림 때문에 휠로 노출할 수 없었던 항목은 전부 확인 완료로 주장하지 않는다. 수정 후 같은 영역을 재검증한다. 빈 프로젝트 배치여서 없는 계획 결과·데이터 객체 결과는 생성하지 않았다.

## 주요 판단

- static `role(v)`가 위성·지상국·데이터·보안·장비 화면에 실기능과 같은 이름의 추가 탭을 만든다. 해당 경로의 예시 탭을 제거하고 현재 모듈 화면만 제공하는 편이 명확하다. 임무 경로는 이미 `mission_workspace`가 화면을 비우므로 실제 추가 예시 탭이 없다.
- DT 루트는 `.panel`/`.view`가 아니어서 작업 영역 스크롤 계약에서 빠진다. 정상 절차·운용 판단의 내부 패널도 기본 flex 축소와 overflow:hidden 때문에 잘린다.
- 데이터의 `dm-module`, `dm-policy`는 필요할 때 읽는 원본 상세이다. 표시 상태·데이터 조치와 별도로 기본 접힘을 적용한다.
- 저장 궤도 구간 도플러와 한 시점 도플러는 동일 계산 화면의 시간 범위별 분석이므로 하나의 통신 분석 작업에서 접근하게 할 수 있으나 계산 모델은 지우지 않는다.
- 지상국 패널에 있는 카탈로그 24시간 조회 버튼과 별도의 선택 위성 가시 시간 패널은 동일 카탈로그 결과의 중복 진입점이다. 등록 지상국/대표 지상국의 입력 차이를 숨겨 합치지 말고 구별된 원본을 명확히 표시해야 한다.
- `catalog_passes` 도움말의 "관측 지상국과 최소 고도각은 시간 탐색에서 적용"은 해당 패널 자체의 등록 지상국 선택과 맞지 않는다. "앞으로 24시간"은 선택한 분석 UTC가 과거일 수도 있으므로 기준 시각을 함께 보여야 한다.

## 이 작업자가 적용한 변경 및 시험

- `tabs/source_data.js`: 원본 모듈 보고는 `details#dm-module-details`, 정책 JSON은 `details#dm-policy-details`로 접었다. 기존 동작 ID, 조회/조치 버튼, 원본 데이터, 소유권 및 3초 조회는 유지한다.
- `source_data_panel.test.mjs`: 상세가 접힘 구조이며 조치 버튼을 숨기지 않는지 확인.
- `source_data_detail.test.mjs`: 새 조회가 원본 상세 값을 갱신하면서 사용자가 펼친 상태와 노드 정체성을 보존하며 쓰기 요청이 생기지 않는지 확인.
- RED: `project_support/u036_data_red.log`, 모듈 상세가 펼쳐진 일반 div라서 실패.
- GREEN: `node --test project_support/tests/browser/source_data_panel.test.mjs project_support/tests/browser/source_data_detail.test.mjs`, 24개 통과 (`project_support/u036_data_green.log`). 전체 회귀시험과 최종 화면 검증은 상위 작업에서 수행한다.

## 상태 갱신 주의점

DT는 `workspace.js`의 `applySharedContext`가 runtime 갱신 시 내부 HTML을 교체하므로 펼침 상태가 유실된다. 임무 상세에서 관찰한 닫힘은 동시 브라우저 탭의 `BroadcastChannel` 상태 방송 후 `workspace.js`의 전체 render 경로에서도 발생한다. `source_missions.update` 자체는 바깥 details를 교체하지 않는다. 원인을 동일하게 단정하지 않는다.

## U036 반영 후 실제 화면 재검증

같은 숨김 탭을 새로고침하여 `/static/scripts/workspace.js?v=u036`와 변경 모듈을 읽은 뒤 1280×720에서 확인했다.

- 데이터는 실제 기능 하나만 남아 중복 기능 구역 내비게이션이 숨겨졌다. 기본 본문 전체 높이는 2740px에서 1954px로 줄었다. 본문545px에서 0→482→893→1303→1409px 끝까지 다시 스크롤했다. 두 상세는 기본 닫힘이고 펼치면 모듈 정보·정책 JSON이 유지된다. 정책을 펼친2523px 전체 내용도1819→1978px 끝까지 확인했다. 데이터 조치 실행은 하지 않았다.
- 보안도 실제 기능 하나만 남았다. 본문523px의 기본 내용은62px 끝, 실행·시각·연결 상세는362px 끝까지 실제로 스크롤하여 확인했다.
- DT 상황판은 높이597px의 `overflow:auto` 영역이 되었고 기본 내용 끝140px까지 이동했다. 모듈별 상태와17개 링크 목록을 모두 펼친 뒤586→1076→1260px 끝까지 확인했다. 표시 실행 경과가 갱신된 다음에도 두 details가 `open:true`, 스크롤1260px을 유지했다.
- 정상 운용 절차는 높이597px/내용759px의 단일 스크롤 영역이 되어162px 끝까지 이동했다. 이전에 잘렸던 여섯 번째 단계, 수락/변경 행, 하단 시나리오 작성 버튼을 확인했다.
- 운용 판단 및 인계는597px/770px,173px 끝까지 이동하여 증거·인계 및 하단 네 카드의 전체 내용을 확인했다.
- 군집 서비스 임무는 두 상세를 펼친638px 내용의148px 끝을 확인했다. SIM 임무는0→396→792→835px, 미리보기 안내를 펼쳐895px 끝을 확인했다. 이후 데이터 화면으로 이동했다가 임무로 돌아와도 세 details 모두 열린 상태가 유지됐다.

실제 화면 증거: `project_support/u036_data_compact.jpg`, `u036_dt_details.jpg`, `u036_normal_scroll.jpg`, `u036_mission_detail_persist.jpg`.

빈 배치에서 존재하지 않는 계획 결과나 데이터 객체 결과는 여전히 만들지 않았으며, 회귀 테스트가 해당 상태별 동작을 별도로 검증한다.
