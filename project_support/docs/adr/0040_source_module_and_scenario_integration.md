# ADR 0040: Reuse senior data/security/settings/scenario contracts in V6

Date: 2026-10-07. Status: implementation in progress.

The independent ISDC application retains AerODT layer boundaries and the pinned senior source. V6 presentation consumes the original isolated-v1 ICD-01 data module, ICD-08 SIM security observations, connection/ICD catalog and PoC assembly/runner/KPI. HTTP routes are explicitly mounted before static fallback; JSON/API failures are not treated as HTML success. Additive compatibility expectations leave the previous API baseline intact.

Data actions bind current accepted deployment scope; changing deployment while awaiting a query or command invalidates that evidence. Reports, catalog objects, replica placement and policy come from the existing scoped module. The browser does not create an independent data store. Original security rules remain SIM observations; an optional external adapter is lazily constructed per application. Its shared unavailable exception belongs in foundation, avoiding an external-adapter dependency on digital_twin.

Module settings remain the original browser client configuration. Saving does not configure or restart server modules. Connection checks are explicit. A TCP connection, UDP name resolution, built-in module response and source planned stub have different meanings. No arbitrary automatic endpoint probe is added. V6 views share the existing SIM socket owner.

PoC advances the existing RuntimeState with the original source advance semantics and uses the existing source node store, accepted deployment, ground store, mission executor and fabric. An explicit scenario display context is validated against the actual paused SIM run and canonical selected UTC. The original browser scenario convention selects Date-millisecond instants; canonical formatting does not increase that precision. Existing Rust queries calculate nodes at that instant. Stored GP/catalog positions are hidden during scenario display, never relabeled as newly propagated SIM coordinates. One Viewer and the existing display observers remain.

Source plan-all-before-commit ordering is preserved. The existing single most-recent native approval is insufficient for multiple source missions. The same runtime owner retains up to 64 immutable approval proofs using FIFO eviction; eviction requires explicit reapproval, with no fallback. Only the approval hash and module sequence may differ from the latest physical scope. Deployment, full definitions, stations, faults, run, analysis UTC, external provenance and module instance remain exact; reset, scenario selection, accepted deployment and fault changes clear evidence. Existing module sequence, task, plan and overlapping-reservation guards remain. Old proofs do not create a second current-state authority. Actual factory tests verify three plans followed by a successful first commit while overlapping commit still fails. No full scenario acceptance is claimed until actual multi-mission playback is verified.

Configuration and source contracts are reused; product completion requires whole regression and actual UI/command/file evidence. RF, HIL, real authentication and equipment remain separately unverified. Port 8891 and the current branch remain fixed.
