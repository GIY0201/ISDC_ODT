# 0002: 서버 UTC snapshot의 표시 투영과 제한된 재생 버퍼

2026-10-02. T018 구현 결정. 외부 API/wire schema와 서버 runtime 계산은 변경하지 않는다.

현재 상태의 소유자는 계속 OrbitRuntime이다. 재생/정지/속도는 최신 서버 snapshot의 UTC를 읽고 기존 selection PUT으로 요청한다. 지정 UTC는 명시적인 selection 명령이다. 클라이언트가 새로운 권위 시계를 만들지 않는다.

브라우저는 응답 수신 performance.now와 서버 current_utc를 기준으로 경과 시간과 배율을 표시 투영한다. 5초마다 서버 snapshot으로 재동기화한다. 응답 수신 기준의 투영이므로 네트워크 지연 0 또는 서버와 정확한 동시 표시를 보장하지 않는다. 화면상의 위치와 고도각은 동일한 표시 UTC에서 계산행을 보간한 값이다.

UTC codec는 서버의 고정 IERS 윤초 snapshot에서 1972년 이후 TAI-UTC 목록을 추출한 작은 표를 사용한다. 해시가 다르면 투영을 거절한다. BigInt ns로 소수초와 양의 윤초를 보존한다. 브라우저의 자체 최신 윤초 표나 Date.parse의 밀리초 절삭을 계산 기준으로 사용하지 않는다. 표 업데이트는 Python 고정 snapshot과 대조 시험을 함께 변경해야 한다. 1972년 이전의 비정수 TAI-UTC 모델은 이번 표시 codec 범위 밖이다.

ISS/제주 fixture의 1초 보간 수치 게이트를 근거로 601행(10분)을 미리 받는다. 남은 범위가 300초 이하이면 1초 겹치는 다음 묶음을 요청한다. 한 쿼리만 활성화하고 이전 유효 버퍼를 수신 중 유지한다. 버퍼는 시간과 유효성 검증을 한 번 수행한 뒤 프레임마다 이진 검색한다. 실제 전파/HTTP를 프레임마다 수행하지 않는다. 오류/범위 밖/잘못된 행은 외삽 또는 합성 fallback 대신 미표시한다.

request ID/revision/input/hash와 EOP/leap hash/frame/profile을 비교한다. 선택 변경 또는 정지 이후 도착한 기존 응답은 폐기한다. 시각화에는 읽기 전용 표시값만 주입하며 하나의 Viewer/entity를 재사용한다. 게임 성능, 다수 위성, 다중창과 실제 통신은 이 결정의 검증 완료 범위가 아니다.
