# ADR0065 PostgreSQL authored workspace definitions

2026-10-07. User authorized a PostgreSQL server after comparing server storage and later migration.

PostgreSQL 18.6 EDB Windows archive runs at 127.0.0.1:5432 under the current OS user. Database isdc_workspace has a separate isdc_app role with SELECT/INSERT/UPDATE/DELETE on two authored-definition tables, no superuser or schema creation. Runtime current state, deployment acceptance, native orbit computations and telemetry are outside this persistence scope. Connection secrets and cluster files live in ignored data/workspace/postgresql with inherited access removed. A per-user ISDC-PostgreSQL login task starts pg_ctl, not a system boot service.

Version 001 stores ground_stations and scenario_drafts JSONB documents in a default shared project namespace. A revision compare-and-swap plus history insert commits in one transaction. REST GET /api/workspace/configurations/status, GET/PUT /api/workspace/configurations/{kind} are additive; original schemas/paths remain exact. PUT requires a custom same-origin header, rejects mismatched Origin, validates bounded nonfinite-free definitions. The application retains its existing access model; this is not an added multi-user permission system. Credentials never reach the browser.

Browser ports retain the original local store contract and a recoverable pending cache. Startup reads server definitions; an absent server definition imports existing local content, backing it up under .before-postgresql first. Revision conflict preserves local pending content and reports failure without automatic retry over another client's edit. Local edit acceptance does not equal server durability; ground and scenario panels expose DB saving/saved/failed state. Existing unconfigured deployments explicitly report browser-only mode. Only these two keys are synchronized.

Backup uses pg_dump custom format plus pg_dumpall globals, an ACL-protected archive and manifest. Isolated restore compares definition values/revisions and history. Application startup reads ISDC_DATABASE_CONFIG; SQL schema migration is an explicit provisioning step, not import-time IO. Changing hosts uses configuration and compatible-version backup/restore; external files need separate copying.

The previous paused RUN-904CE008D00B had forty deployed nodes that bounded resume could not restore. The user explicitly authorized initialization and DB activation. Live8891 was restarted with the product stored orbit factory; new run RUN-E578A57A4EB9 was paused and saved GP selection restored. Existing browser station definitions imported, authored test scenario saved, browser refresh confirmed both kinds, and actual definitions/history passed isolated backup restore. Runtime state persistence is not part of this decision.
