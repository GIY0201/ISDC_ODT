# ADR0024 지상국 브라우저 설정의 실패 처리

선배의 ground_segment.js(1a1e002) 정상 추가·편집·활성화·삭제·선택·초기화와 schema1 저장 형식을 재사용한다. 기존 모델을 조립 지점에서 주입하며 import 시 localStorage에 접근하는 singleton은 옮기지 않는다. 이 목록은 브라우저별 설정 초안이며 서버 현재 상태가 아니다.

원본은 읽기 실패를 기본 지상국으로 대체하고 저장 실패를 무시한다. 이식본은 없는 키(null)에만 기본 세 지점을 적용한다. JSON 손상, 형식·개수·중복 ID·숫자 오류 또는 읽기 권한 실패는 ready=false/error로 알리고 마지막 목록과 저장 bytes를 보존한다. 이 상태에서 편집은 차단하며 명시적 재읽기 또는 초기화로 복구한다. 오류 상태의 목록은 계산 입력으로 사용하지 않는다.

모든 수정은 후보 검증과 저장 성공 후에 목록·선택·번호를 함께 채택한다. 저장 실패는 예외와 error 이벤트를 제공하며 기존 상태를 보존한다. 갱신의 입력 검증 실패는 원본처럼 문자열 배열을 반환한다. UI는 저장 예외도 표시해야 한다. 반환값·프리셋은 사본이며 관찰자의 예외는 다른 관찰자와 채택 결과에 영향을 주지 않는다.

입력 숫자는 유한 number, 대역은 S/X/Ka의 비어 있지 않은 배열이어야 한다. 원본 생성자의 묵시적 대체값으로 잘못된 편집을 숨기지 않는다. 다만 원본 통신 UI의 직접 추가 버튼이 보내는 name:''는 순번 이름 요청으로 유지한다. 저장된 오래된 선택 ID는 원본처럼 null로 정리한다. 초기화는 원본처럼 번호를 유지한다. storage:null은 명시적 memory_only이며 영구 저장이라고 표시하지 않는다.

원본 고정 hash 실행 trace, 실패 시 원자성·복구·사본·수용량 시험을 별도로 검증한다. 실제 UI/다중 창 편집 충돌·계산 입력 차단·통신망 연결은 T077/N008 완료 조건으로 남는다. 단순 reload 시험을 전체 다중 창 검증으로 주장하지 않는다.
