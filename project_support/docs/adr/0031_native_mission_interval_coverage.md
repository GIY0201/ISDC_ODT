# ADR0031: Source interval algorithm with native points and explicit sampled coverage

Status: internal eclipse producer accepted; other window kinds/HTTP/controller/V6 acceptance pending.

Retain source scanIntervals predicate, transition and inside-edge bisection semantics while awaiting the existing native query instead of invoking JavaScript dynamics. No second propagator/history/clock is introduced. Ported flow is checked against an offline capture of the unchanged original function and an actual installed Rust-versus-original-JS3h/two-node oracle. Source source_commit and units/quality remain explicit.

Repair source unaligned-end omission by querying the exact supplied end. Reject any required coarse/refinement row error/malformed/hash/context identity rather than converting failure into empty windows. Window/row bounds are explicit failures. Retain cancellation and only publish complete local result after all refinement calls succeed.

Coarse sampling may miss/merge short intervals. Status sampled, resolution and boundary tolerance are mandatory; do not claim mathematically exhaustive coverage, SC visibility acceptance, real RF/HIL or complete N011. Full contact/access/external window assembly and shorter-event/peak coverage require further source/API/app verification. A source-like engineering sampled planner can only be exposed with those limitations visible and appropriate current input proof.

Existing point query/executor/receipt decoder owns native execution. Local transition/bisection work is invocation-only, no duplicate runtime/mission store. Strict24h supported interval prevents silently clamping an up-to72h deadline. Larger coverage needs an explicit producer contract rather than dropping late windows. Original samples/track/ICD03 equations unaffected. Current change adds no HTTP endpoint and does not restart8891.
